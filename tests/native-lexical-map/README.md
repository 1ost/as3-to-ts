# Exact lexical proof ownership in complete source maps

`NativeCallableClasses` validates every source-map declaration with the lexical plan for that declaration's exact source and qualified name. The current emitter's plan is reused only for its own identical source; other entries build independent plans with the same lexical provider and typed-local opt-in. Sibling plans are used for metadata proof and class-member classification. They do not publish runtime scopes or emit sibling method bodies.

Both complete captured Object-root classes remain in the map for every emission. All methods and initializers of both classes are emitted and executed. Reversing map insertion order must produce identical generated output. There is no source pruning, method substitution, copied native method implementation or synthetic reflection in the successful fixture.

Two original Flash captures retain 21 identical rows and complete Class and instance `describeType` XML for both classes. The captures prove separate private/protected instance members, private/static state, bound method identity/calls, cross-class static access, wildcard receiver dispatch and sibling construction. The evidence verifier authenticates source/tool/capture receipts and compares complete XML semantically, including Class factory versus instance traits.

Run `npm run build` and `npm run test:native-lexical-map` with `LAYA_ENGINE_REPOSITORY`, `PLAYWRIGHT_MODULE` and `PYTHON` pointing to the real local tools. The runtime runner archives engine commit `6aba63414d3e63db6ebe120af9c396741759e5cc`, bundles its actual provider, generates actual provider declarations and validates both ES5 and ES2015 consumers in Node and Chromium, with typed-local opt-in both off and on. This does not assert whole-engine ES5 compatibility; the provider bundle uses ES2020. Dependency graphs retain exact source and tool type-file hashes.

The 25 compiler controls cover missing lexical authority, sibling source/record/qname/hash swaps, missing public or storage surfaces, missing lazy identity, unsupported ancestry/interfaces, signatures/accessors, foreign slots/locals, lexical constants, nested functions and declaration-order restrictions. Modified sources are explicitly compiler rejection controls, not successful original-backed classes.

Metadata proof planning is not operation readiness. A separate control keeps an unsupported `delete secret` operation in the complete sibling: sibling metadata planning succeeds while emitting the other class, and emitting the actual owning complete class rejects. Callers must emit every required complete source before claiming group readiness. This patch adds no group-wide readiness flag and relaxes no operation guard.

The intact five maintained timing source and metadata maps remain held. PropTween's prior incorrect sibling proof error now identifies TweenPlugin's genuine foreign-local prerequisite. TweenPlugin and TweenCore still require foreign local reference identity; TweenLite and SimpleTimeline still require derived-class lexical/metadata integration. Accessor entry, typed method signatures and unsupported operations remain separate prerequisites. The frozen prior research packet is retained for source and reflection provenance.
