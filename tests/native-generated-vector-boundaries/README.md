# Generated Vector boundary lowering

Run npm run tsc, then node tests/native-generated-vector-boundaries/run.cjs,
also with --combined for overlapping scalar/reference signature passes.
All nine retained AS3 subjects are emitted unchanged: four classes and five
interfaces, including maintained IOrder, ICommand and IOrderManager. The separate
observer compares all 33 default, argument, return, assignment, local, authored
Error-catch and arity outcomes with the authenticated AIR packet on ES5/ES2015
in Node and Chromium. Generated/provider type diagnostics must be zero.

An explicit vectorProviderModule binds interface/primitive specializations in
the declaration domain without importing source class implementations. Generated
annotations use the common AS3Vector type; public instance fields and callable
entry/return/local conversions use the matching common property specialization.
Interface signature annotations use nativeVectorTypes with the same exact plan.
No Vector Array substitution or authored body rewriting is used.

Eight rejection guards retain Vector construction, static/constant/accessor or
private storage, optional parameters, source class element publication and nested
specialization publication as separate prerequisites. Three comparison controls
detect row omission, ordering and loss of raw undefined assignment results.

The two arity observations establish name, errorID and pre-body timing only.
Their existing callable helper still allocates a host ArgumentError-shaped Error;
source Error catch/nominal identity for arity failures remains a separate gap.
Vector coercion failures in the full authored catch use genuine source TypeErrors.
General builtin TypeError Class identity, complete Vector reflection and actual
bulk/application admission are not established by this focused fixture.
