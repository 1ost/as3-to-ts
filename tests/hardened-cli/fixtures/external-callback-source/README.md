# Generated ExternalInterface callback registration

This authored diagnostic preserves the original registration forms: a bound private no-argument String handler and a conditionally registered Object-to-Object handler. Private text and a public counter make receiver binding observable. It does not replace or modify application source.

The opt-in CLI regression creates an authentic SDK/target profile, qualifies and transpiles the retained source twice, verifies deterministic emitted code, and executes the generated authority-first entry against the selected real shared ExternalInterface module. An explicitly installed host exercises the primitive callback with a foreign receiver and checks identity-safe revocation. Object callback registration is checked; structured callback invocation is deliberately untested.

Set FROZEN_LAYA_ROOT (or HARDENED_FIXTURE_LAYA), HARDENED_FIXTURE_AIR_SDK and HARDENED_FIXTURE_FFDEC, then run `node --test tests/hardened-cli/external-callback-source.test.cjs` from the compiler root with current built CLI output. No environment variables skips this opt-in test; incomplete configuration fails. Failed outputs are retained for diagnosis.

The precursor runner passed two deterministic transpiles and four primitive invocations against compiler 76dab4d521c12af0a5a9aa64a78cd6cce31694f7. This is generated integration evidence, not a native structured-callback parity claim.
