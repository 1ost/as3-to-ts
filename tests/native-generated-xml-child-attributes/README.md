# Generated XML child attribute paths

Run `npm run tsc`, then `node tests/native-generated-xml-child-attributes/run.cjs`.
The production class module factory emits the complete original `Config` and
`Reader` sources retained in the engine's `generated-xml-child-attributes` AIR
packet. ES5 and ES2015 each match 26 generated-method observations plus the
shared-helper identity row in Node and Chromium, with zero type/browser errors.
`verify.cjs` checks the retained receipt and input hashes.

The compiler lowers literal named child paths on typed XML receivers, attributes
across the resulting XMLList, and selected-list length/string queries. Exact
planned public static methods returning canonical XML can be receivers; their
bodies and receiver expressions retain the normal generated call path. The two
`Config.read()` expressions execute exactly twice, and a null return throws on
the first read. Repeated attributes, missing children and namespaces compare
against Flash, rather than JavaScript property or numeric conversion behavior.

Twelve compile rejection checks cover missing/mismatched bindings, lexical class
shadows, Object return/root types, writes/deletion/increment and child invocation.
Four runtime checks reject forged XML and XMLList values from the XML field and
preserve its prior value. Method-name child selection, arbitrary receiver calls,
QName, mutations and general XMLList scalar calls remain unqualified. The fixture
does not establish collection asset loading or whole-game startup.
