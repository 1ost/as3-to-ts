# Generated accessibility reference binding

Run `npm run tsc`, then `node tests/native-accessibility-reference/run.cjs`.
The isolated engine must provide `AS3CanonicalAccessibilityReference` and the
authenticated `nativeFlashOracle/accessibility-reference` packet.

The unchanged complete AccessibilityHolder.as emits through the production
module factory on ES5 and ES2015. All 31 AIR observations match in Node and
Chromium with CSP forbidding runtime compilation. They cover default and supplied
constructor references, fields, parameters, returns, a readonly getter, is/as,
nullish conversion, invalid inputs and conversion hooks. Generated code and its
provider graph have zero TypeScript diagnostics.

The explicit `nativeAccessibilityReferenceModule` must match the declaration
plan's provider and import binding. Seven compiler controls reject missing or
mismatched authority, shadowed type names and native subclass admission. Twelve
runtime controls cover exact tokens, genuine native descendants, forgeries,
proxies without traps, same-name foreign declarations, absence of fabricated
reflection, and retained instances after module retirement.

This is nominal reference support, not AccessibilityImplementation Class
reflection, dynamic construction, generated TextAccImpl inheritance, assistive
technology delivery, or complete Sprite/BaseModule admission. The bulk-worker
integration is tested separately in OP2's `test_bulk_accessibility_reference.mjs`.
