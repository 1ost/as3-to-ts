# Generated Sprite returns

Run `npm run tsc`, then `node tests/native-generated-sprite-returns/run.cjs`.
The complete subject comes unchanged from the engine's authenticated
`nativeFlashOracle/sprite-returns` packet. Factories use the captured SWF's
authored dimensions/hash for native Sprite allocation context.

`run-1kCgQ2` matches all sixteen AIR rows on ES5/ES2015 in Node and Chromium
under CSP, with zero type diagnostics, four domain/forgery/lifetime checks,
four compiler rejection controls and one applied coercion-removal mutation per
target. The mutation must build before failing the forged-Sprite return guard.
Production factory output is deterministic; transitive type/provider inputs
are hashed and verified after execution.

With the explicitly bound canonical DisplayObject reference module, Sprite
returns now use the existing nominal display proof and completion-aware return
coercion. The native Sprite binding remains explicit. Other native returns,
missing display qualification, bare typed returns and fallthrough remain held.
Cases include static/instance methods, fresh allocation, nullish results,
unrelated native displays, catch-invalid returns, finally replacing valid or
invalid pending returns, bound calls and source arity.

The observer uses the existing nativeDisplayProjection state-only NoRender host
with actual shared Sprite providers. It does not claim canvas rendering, frame
scheduling, generated BlurLayer fidelity or whole-client account validation.

Event-return regression `run-fqg2LV` passes 24 AIR rows; Date-return regression
`run-GSODFH` passes 25, both targets/runtimes with zero type diagnostics.
Generated Sprite allocation `run-wVJV8L` passes eighteen retained projection
states per runtime/target and fifteen guards, with no added type diagnostics.
