# Generated TextLine return coercion

BaseCompose.createTextLine returns a native TextLine. The authenticated provider
and reference option were present, but generated method return admission omitted
TextLine. Admit it only with the existing matching nativeTextLineReferenceModule
contract, using the existing common property coercion and canonical declaration.
No runtime bridge behavior or local application substitute is added.

The unchanged linereturn.Subject source is compiled by the source-class factory.
Two identical AIR 51.3.4 non-debugger captures supply 85 observations. Both ES5 and
ES2015 match in strict-CSP Chromium with initialized Laya and real graphic-backed
TextLines. Cases cover valid/wrong native and structural values, null/undefined,
public/private/protected/static returns, getters, optional/arity checks, callback
results, throws, branching, finally effects/overrides and released/recreated lines.
Conversion hooks are not called. Return conversion follows body effects.

Six compiler guards reject absent/mismatched/malformed authority and copied plans.
Three browser host guards reject forged/proxied/copied TextLines. Two applied
mutations per target bypass an emitted return conversion or retain undefined on
an original source return; each changes a specific AIR observation. Generated
source and actual provider strict type checking have zero diagnostics.

Run npm run tsc, then node tests/native-generated-textline-return/run.cjs.
The default engine is ../LayaAir-op2-textline-return-review; use
LAYA_ENGINE_REPOSITORY to override it. verify.cjs --check-current authenticates the
complete retained inputs, AIR source/captures, bundles and comparisons.
verify-adjacent.cjs --check-current authenticates fresh TextLine constructors (31
AIR rows in Chromium) and TextBlock reference/return coercion (19 rows in Node and
Chromium) on both targets with this compiler. Previous proof archives are intact.

This does not qualify font-backed/mixed composition, the complete BaseCompose
factory or the real H5/account flow. Errors compare class and ID, not full strings.
